3. Como os números devem funcionar

No WMK, um servidor atribui um código de controle de seis dígitos. O cliente guarda o código e seu segredo para recuperá-lo depois de reiniciar. A documentação do projeto diz que códigos sem uso por 180 dias podem ser liberados. O código não é equivalente à identidade criptográfica: o host também guarda um par de chaves, e o controlador verifica a chave do computador nas conexões seguintes.

Recomendação: manter o código de 6 dígitos para localizar o equipamento, manter verificação criptográfica de identidade e oferecer apelidos como Empresa Alfa / Financeiro. Não inventar um sistema paralelo de códigos sem migração do protocolo. Não mostrar o código de pareamento permanentemente na tela principal.

4. Perfis de permissão que devemos construir

Somente visualizar

Permite apenas assistir à tela; não envia teclado, mouse, arquivos nem clipboard.

Suporte assistido

Permite visualizar e controlar após aceite; arquivos e funções administrativas dependem de confirmações separadas.

Suporte com arquivos

Permite solicitar upload/download dentro de diretórios escolhidos pelo cliente, com escopo temporário e auditoria.

Host corporativo

Acesso recorrente mediante cadastramento de técnico confiável, autenticação forte, permissões restritas, logs e revogação. Não ativar acesso aberto por padrão.

Os perfis do AnyDesk demonstram a separação de tela, teclado, clipboard e gerenciador de arquivos; isso é uma referência de requisitos, não uma implementação já existente no WMK.

5. A verdadeira solução para zero configuração

Não basta esconder campos de endereço e certificado. O servidor WMK deve existir, estar disponível pela Internet e ter certificado verificável embutido na versão distribuída. A hospedagem será responsabilidade do operador do serviço.

Distribuição assinada WMK (Windows)
    │
    ├─ Relay WMK pré-configurado + fingerprint fixado
    │     └─ Atualização confiável de certificados (sem TOFU cego)
    │
    ├─ Abrir e mostrar ID de 6 dígitos
    │
    ├─ Receber pedido com identidade do técnico
    │     ├─ Somente visualizar
    │     ├─ Controlar mouse/teclado
    │     └─ Autorizar arquivos separadamente
    │
    └─ Desconectar / revogar a qualquer momento
Limitação importante: uma versão atual do WMK ainda não oferece servidor público WMK configurado e homologado. O build no GitHub Actions, isoladamente, não resolve conexão pela Internet. O executável de produção depende de relay real, certificado, testes, assinatura e política de atualizações.

6. Tela WMK proposta, mais simples que a referência

Receber ajuda

Seu código: 123 456 (exemplo). Copiar código, status Online e botão Encerrar acesso. Sem menus técnicos na primeira tela.

Acessar computador

Campo para seis dígitos + botão Conectar + Meus dispositivos. Qualidade automática; opções técnicas ocultas.

Durante a sessão

Barra com Capturar tela, Arquivos, Chat, Tempo, Monitores e Desconectar. Funções ainda não implementadas devem aparecer desabilitadas, nunca fingir funcionamento.

Configurações

Geral (idioma/tema), Acesso e Segurança, Arquivos e Capturas, Vídeo/Áudio, Rede Avançada, Sobre. Modo básico por padrão.

7. Ordem de execução

  1. P0 — Acesso real: instalar em dois Windows, confirmar identificação, pareamento, controle remoto e revogação.
  2. P0 — Zero configuração: configurar relay WMK confiável no build, criar verificação de conectividade, entregar executável com instalação assistida.
  3. P0 — Permissões: matriz de autorizações por sessão e solicitação explícita para arquivos.
  4. P0 — Arquivos: canal de transferência bidirecional independente, tamanhos grandes em blocos, progresso, cancelamento, hashes e pastas permitidas.
  5. P1 — Evidências: validar captura PNG remota; pasta de destino selecionável e histórico.
  6. P1 — pt-BR: todas as mensagens do cliente React, menus Rust, serviço, instalador e Android.
  7. P2 — Empresarial: grupos de empresas, técnico por papel, autenticação multifator, auditoria, administração central.
